# GlassDesk 1.0

> 发布日期：2026-10-14 ｜ 标签：`v1.0`

本版为功能与稳定性版本：补齐 Dock 右侧时间、系统托盘面板与音频控制，并修掉一批会影响数据、窗口归属与自动隐藏的缺陷。

> 版本号从 `1.3.1` 改为 `1.0`：请确认更新通道不会把这次变更当成降级。程序集标识（`0.2.2.0`）刻意保持不变，`SOURCE-PROVENANCE.json` 记录的仍是原始快照来源，未改动。

## 新增

- **Dock 时间精确到秒**：默认显示 `HH:mm:ss`，设置中心可关掉只显示到分；外框预留宽度随该开关调整，时间不会被裁掉。
- **系统托盘面板（应用托盘）**：收纳 Windows 通知区域的图标，并把折叠区（溢出浮层）里**正在运行**的第三方程序一并列出，两者使用同一套真实图标（取自系统登记表里的图标快照，退回可执行文件图标）。
  - 每个格子右键可：**隐藏**、**固定到最前**、**退出**；
  - 面板底部保留「恢复隐藏的图标」；
  - 面板打开期间约每 3 秒自动重读一次托盘，新登录的账号、刚启动的程序会自己出现。
- **音量页**：音量条右侧的展开按钮进入「输出设备 + 音量合成器」两栏——可切换默认播放/录音设备，也可按应用单独调音量与静音。
- **隐藏系统任务栏**：把任务栏收起来并阻止鼠标顶到屏幕边缘把它重新唤起；退出 GlassDesk 时恢复，并还原你原来的自动隐藏设置。被结束进程时由一个守护进程代劳恢复，下次启动也会先自愈。
- **右键入口**：Dock 空白处 → 任务管理器；Dock 最左侧启动台 → 退出；启动台右上角 → 设置中心。
- **窗口调用顺序**：左键固定图标时按「身份 → 映像路径 → 该程序现有顶层窗口」三级依次尝试，**优先点亮已有窗口**，确实没有才启动。
- **设置中心**：窗口默认 1000×800（DIP），随系统缩放百分比；超出屏幕工作区时自动收敛。
- **动画帧率自适应 60–300Hz**：动画本身跑在合成帧回调上（合成器给多少帧就跑多少帧），而**轮询节拍**改为量取相邻帧的实际间隔——60Hz≈16.7ms、300Hz≈3.3ms，不再写死 16ms。丢帧（间隔过大）不采信，避免把一次卡顿记成"这台机器就是 30Hz"。

## 修复

- **数据丢失**：文档存在但读不出来（被占用、权限不足、被安全软件扣着）时，不再被当成「首次运行」返回默认值——原先下一次保存会覆盖真实设置与应用库，且首次保存不写备份。
- **窗口归属**：带身份（AUMID）的应用条目现在也能认领**没有身份**的窗口。此前这类条目匹配不到任何窗口，导致「合并固定图标与运行中的应用」拨了没反应、运行圆点不亮、左键点不亮已有窗口——本机 107 个开始菜单快捷方式里有 24 个属于这种。
- **运行条分组**：身份不同的窗口不再因为共享宿主进程（如 `ApplicationFrameHost.exe`）被并成一个磁贴；同一进程的多个无身份窗口不再丢失窗口或出现重复磁贴。
- **重新定位**：不再保留旧程序的身份，避免点亮旧应用的窗口；保存失败时连同身份一起回滚。
- **托盘面板**：面板自己收起时不再把 Dock 卡在「永不自动隐藏」；改动设置不再丢失抑制状态；拖动不再误改**上次点过**的应用；隐藏图标不再被折叠区原路加回；系统声音会话不再混进音量合成器；设置页不再自称「Beta」。
- **任务栏**：启动自愈现在真的会恢复（此前被一处提前返回挡住）；改为先拉起守护进程再隐藏；确认循环加了异常保护（此前一次意外会杀掉整个进程）；新接入的显示器任务栏也会被隐藏。
- **快捷键**：录制快捷键不再把鼠标键、热角等其它设置重置为默认值。
- **其它**：合成器页用过一次后不再粘住；性能休眠结束后运行条会刷新；自定义图标保存失败时不再留下「内存指向不存在的文件」；设置窗口标题里的验收 harness 字符串已改掉；三处「不碰任务栏窗口」的说明与实际实现对齐。

## 打包与分发

- **exe 安装包**：`GlassDesk-1.0-Setup.exe`（单文件，约 138 MB），图形安装向导——可改安装路径、可选创建桌面快捷方式、完成后可立即运行。行为与仓库里既有的 `packaging\GlassDesk-Capture.iss` 对齐：**用户级安装**（不弹 UAC）、装到 `%LOCALAPPDATA%\Programs\GlassDesk`、开始菜单快捷方式必建、卸载信息写入 `HKCU\...\Uninstall\GlassDesk.Independent_is1`、安装前先结束正在运行的实例；安装器自身也会在「应用和功能」里出现，支持 `--uninstall` 与 `--silent`。
- **打包脚本**：`build\package-setup.ps1`——暂存发布件（排除 `Data\*`）→ 压缩为内嵌载荷 → 生成单文件安装器。不依赖 Inno Setup，只用已安装的 .NET SDK。
- **上传脚本**：`build\upload-to-github.ps1`——提交并推送，推送前会核对暂存文件里有没有超过 GitHub 100 MB 上限的，有就中止。
- **代码精简**（不影响行为，除注明者）：`IsExpectedFailure` 的 COM 失败过滤器由三份收成一份（顺带补齐 `SystemVolume` 少判的 `InvalidOperationException`，**这是行为变化**）；八处 `StrategyBasedComWrappers` 收成一份共享实例；删除 `ShowRunningIndicator`、`TrayIconEntry.HasBounds`、`RunningProcess.StartedAt`、`TaskbarAutoHideEnabled`、`BlockTaskbarEdgeReveal`、`LauncherSettings.FullscreenMode` 与被动唤出三件套（`AutoHide`/`EdgeRevealEnabled`/`EdgeHotzoneSize`）；`TrayIconCatalog` 里一行转发方法并入实现。
- **死代码判据的教训**：`PassiveRevealPolicy.CanReveal` 一度按「无生产调用者」删除，但 `Phase6DisplayTests` 有六条用例**用反射**核对它——它是那组门的规格表，已恢复。单看调用者数量不足以判定死代码。

## 已知限制与待办

- **多实例软件**（例如同时登录两个 QQ 账号）：点「退出」结束的是**全部**实例——按程序路径无法区分你点的是哪个账号，因此标签统一为「退出」，行为是全部结束。
- **折叠区图标的点击**是「激活已有窗口，没有则启动」，不是原程序自绘的托盘菜单动作；那需要展开系统浮层。
- **折叠区**只列出登记过、且此刻确实在运行的程序；图标是登记时的快照，程序运行时换图标不会即时反映。
- **Dock 放大峰值**：设置里记录 1.35（D-21 定的产品值，多处测试守着），而渲染实际使用常量 1.15，两者不一致，待产品决策后统一。
- 下列修复目前由探针或代码路径确认，**尚未**沉淀为仓库自动化测试：托盘面板收起后的抑制归零、两处弹层抑制配对、合成器复位、休眠后运行条刷新、自定义图标回滚、窗口调用顺序的第三级。
- `tests/GlassDesk.AppServices.Tests` 中约 49 项与打包/验收脚本相关的测试在缺少 `build/package.ps1`、许可与清单文件时失败，属预先存在；其中一项在 48↔49 之间波动，会影响回归判断。
